Glosario — Gestión de Red con SNMP

No va a haber explicación en vivo de este tema: todo lo que necesitan está aquí. Léanlo con calma en grupo antes de tocar la terminal — el repaso del final se basa en esto.

1. ¿Qué es la Gestión de Red?

Es el conjunto de actividades (herramientas, protocolos y procesos) para monitorear, controlar y mantener una red de datos: saber qué equipos hay, cómo están funcionando, detectar fallas antes de que el usuario se queje, y mantener la red segura.

El estándar más usado en el mundo real para hacer esto es SNMP (Simple Network Management Protocol).

2. El modelo FCAPS

FCAPS organiza TODO lo que implica administrar una red en 5 áreas. Es un mapa mental que usan los administradores de redes reales:

F · Fault (Fallas)Detectar, registrar y resolver fallas: un enlace caído, un servicio sin responder.
C · ConfigurationLlevar control de cómo está configurado cada equipo y sus cambios.
A · AccountingRegistrar uso de recursos: quién consume cuánto ancho de banda, para facturar o auditar.
P · PerformanceMedir rendimiento: carga del procesador, memoria, tráfico — para anticipar problemas.
S · SecurityProteger la red: credenciales, accesos, vulnerabilidades expuestas.

Ejemplo: una community string "public" expuesta por defecto es un problema de Security. Un panel que muestra la carga del CPU en vivo es Performance.

3. Arquitectura de SNMP

Agente y Manager

  • Agente (software snmpd): vive DENTRO de cada equipo a monitorear (router, switch, servidor, PC) y responde preguntas sobre ese equipo.
  • Manager (herramientas snmpget, snmpwalk, o un software como un NOC Dashboard): hace las preguntas, generalmente desde un puesto central.

MIB y OID

La MIB (Management Information Base) es el catálogo completo de datos que un agente puede entregar, organizado como un árbol. Cada dato tiene una dirección numérica única dentro de ese árbol: el OID (Object Identifier).

Ejemplo: el OID 1.3.6.1.2.1.1.5.0 siempre significa "nombre del equipo" (sysName), en cualquier dispositivo SNMP del mundo.

4. Community string y versiones de SNMP

En SNMPv1 y v2c, la autenticación es una palabra simple llamada community string — no está cifrada, viaja "en texto plano".

  • rocommunity → solo lectura (Read-Only).
  • rwcommunity → lectura y escritura (Read-Write) — mucho más riesgoso si se filtra.

"public" es la community de solo lectura que viene por defecto en miles de equipos reales — un hallazgo típico de seguridad.

SNMPv3 corrige esta debilidad: agrega autenticación de usuario real y cifrado del tráfico.

5. Puertos y formas de consultar

  • UDP 161 — el Manager pregunta al Agente (consultas normales: snmpget, snmpwalk).
  • UDP 162 — el Agente avisa al Manager por su cuenta (traps / alarmas).

Polling vs. Traps

Polling: el Manager pregunta repetidamente, cada cierto tiempo (así funciona un dashboard que se actualiza solo). Traps: el Agente notifica espontáneamente cuando pasa algo importante, sin esperar que le pregunten.

get vs. walk

snmpget trae un solo valor puntual. snmpwalk recorre todo un subárbol de una vez.

6. Herramientas complementarias (para saber que existen)

  • Grafana: arma dashboards visuales bonitos a partir de datos ya recolectados (no habla SNMP directamente).
  • LibreNMS / Zabbix: plataformas completas de monitoreo que sí hablan SNMP y descubren equipos automáticamente.
  • Prometheus + snmp_exporter: combinación moderna que traduce SNMP a un formato que Prometheus/Grafana entienden.
